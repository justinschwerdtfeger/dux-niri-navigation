# Codebase review

Justin Window Tabs (`justinNavigation`) and Justin Workspaces (`justinWorkspaces`) target Dux Shell 2.0.0, including the user's configurable widget inset. The development source is pinned to fork revision `0bd677b213a445d4012e37968f8beca0acd90012`; its common widget submodule is `ebf5e6c002da1bdaa4aaa2f319fea7b8507abc42`.

## Current implementation

- Both widgets use the host's `widgetThickness` in either orientation. The old horizontal full-bar override is removed. Dux owns inset, pill/segment backgrounds, and outlines; buttons retain their local hover and focus behavior. Each plugin optionally sets 0–48 px of padding at each end through a local host-pill config; by default it follows the bar. The original bar config and button thickness remain unchanged.
- Controls use Dux 2.0's `DIcon`, `DTextField`, `DScrollbar`, and `StyledText` from `qs.DCommon.Widgets`, with `DTooltip` and `DPopout` from `qs.Widgets`. The picker passes its source item when positioning the popup.
- `BarGeometry` reads Dux 2.0 section entries and spacing to reserve siblings, the native overflow trigger, and occupied neighboring sections, ignoring its own changing extent and an empty center. Actual pill padding is subtracted once.
- The project [plugin skill](../skills/dms-plugin-dev/SKILL.md) adapts the fork's widget guidance and is linked from `AGENTS.md`. Tooling and the devcontainer target the same fork and `DCommon` imports.
- Column scrolling uses Dux 2.0’s `focusColumnLeft/Right` and per-bar reverse-scroll option. The link helper installs into Dux’s `dms/plugins` directory without touching legacy paths.
- Bar buttons use Dux’s actual `BarPillSurface` for pill/flat resting and pressed rounding; the host supplies joined section corners. Focus rings and drag backgrounds follow that radius. Sidebar and picker buttons retain a generic-radius override.
- Bar icon/font scale and maximize options feed the actual tab labels, app/favicons, launcher/overflow controls, and workspace symbols. Larger content raises individual readability minimums; artwork may occupy the full bar cross axis without enlarging the inset button backgrounds, and vertical rows reserve sufficient length for the requested icons; picker and standalone sidebar sizing remain independent.
- Workspace mouse areas span full-thickness rows aligned to the actual plugin host origin. Reading ancestor positions accounts for centered-loader rounding at fractional sizes. Picker targets remain local; cross-axis edges dispatch workspace/picker actions in component tests, while disabled targets, gaps, and outside regions stay untouched. The user reports the preceding symmetric-offset correction still missed clicks after restarting the normal bar; visible acceptance of the host-alignment correction is pending.
- The launcher-only horizontal controls grid uses one column. Three fixed columns retained an extra spacing unit with hidden arrows, clipping the last fitting tab’s right edge. Geometry tests reproduced the clipping before the correction and now pass at fractional and large sizes.
- Existing output scope, live IDs, dynamic workspace lifetime, exact titles, proportional widths, reorder acknowledgment, keyboard activation, middle close, and optional standalone sidebar contracts remain in force.

## Independent review

The requested read-only sub-agent review found one P2 issue: Dux's separately created native overflow button was missing from the space budget. Horizontal and vertical regressions reproduced an over-allocation of 42 px (30 px trigger plus 12 px gap). The adapter now reserves Dux's `overflowTriggerSize` whenever `overflowCount > 0`, including before the button finishes incubation. Tests exercise a full strip beside an always-overflow sibling and a trailing section, multiple hidden entries sharing one trigger, and release of its reservation when overflow disappears. No other actionable findings were reported. The correction passes the complete check suite and both new regressions.

The follow-up review confirmed the pinned Dux API usage and found one P2 issue: increasing row lengths with icon scale could hide the unchanged active workspace in an overflowing rail. Horizontal and vertical regressions reproduced it with the last workspace selected. Row-length changes now schedule a reveal after applying pending layout updates, preserving the selected delegate and viewport size. The correction passes the full suite; no other actionable findings were reported.

The workspace inset hit-target review found no blocking issues in the preceding symmetric-offset implementation. Its eight whole-pixel cases did not cover rounded ancestor positions at fractional widget sizes. The host-alignment follow-up adds those cases and the suggested disabled/negative-boundary checks; eight of the expanded 24 cases reproduce missed clicks without the new alignment. Independent review found no blocking issues in this follow-up: explicit ancestor reads track rounded placement and resizing, the inspected wrapper uses compatible translations, and the fixture matches its relevant nesting and fallback mouse ordering. Clipping preserves input boundaries, disabled behavior, primary-axis gaps, and visible button thickness. The reviewer confirmed the supplied red/green and full-suite logs. This establishes a component defect and correction; whether it explains the user's runtime failure still requires live Dux/Niri pointer acceptance.
