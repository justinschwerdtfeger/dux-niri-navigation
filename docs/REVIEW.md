# Project review

This whole-project audit covers runtime QML/JS, session state, the favicon bridge, manifests/settings, packaging/installation, development tooling, tests/mocks, style, architecture, comments and documentation. The starting revision is `431fa0e`. One read-only subagent performed the first audit; a different agent reviews the findings and resulting changes afterward, with no overlapping subagents.

The development target is Dux 2.0 fork `0bd677b213a445d4012e37968f8beca0acd90012`, common-widget submodule `ebf5e6c002da1bdaa4aaa2f319fea7b8507abc42`, and Quickshell 0.3.1. The pinned source and local fork `c5b058c83e6ac77420e43b8e7dd844a652cef679` were inspected. No installed/active desktop source is available here. [Development](DEVELOPMENT.md#inspected-baseline-and-host-contracts) lists the inspected API boundaries.

## Findings and resolutions

- **P1 — vertical pointer dragging never started.** `NavigationButton` checked only scene-X displacement, so straight vertical motion could not reorder icons, title rows, rotated tabs or sidebar windows. The threshold now accepts movement on either axis. Five pointer-level cases cover horizontal, vertical icons/titles and both rotated edges, including below-threshold motion, focus on press, drop dispatch and no second activation on release. The previous vertical tests bypassed this boundary by calling drag functions directly.
- **P2 — Escape after mouse expansion lacked QML focus.** The sidebar expand button now takes focus on an explicit left press. Its existing Escape test no longer manually assigns focus. Hover expansion does not acquire focus. Native Wayland keyboard routing still needs acceptance.
- **P2 — pointer entry during acknowledgment could open a held sidebar.** Hover scheduling now rejects all interaction holds, including entry after a hold has already begun. A new event-order regression reproduces the failure. Tab, launcher and overflow presses share one held-anchor state, so controls participate in the same hold.
- **P2 — a held expand button could race its pending hover timer.** The second reviewer reproduced expansion during a held mouse press followed by collapse on release. The hover hold now includes the separate expand button. Its enabled condition depends only on navigation/acknowledgment holds, so its own press cannot disable and cancel itself. A real 260 ms press with the default 200 ms hover delay verifies no expansion during the hold, one expansion on release and natural Escape collapse.
- **P2 — horizontal tooltips overlapped bars with a positive widget inset.** Top/bottom anchors used button height while vertical anchors used full bar thickness. All edges now clear the full bar. Four geometry cases cover top/bottom/left/right with a deliberately thicker host bar.
- **P2 — fresh development builds depended on a moving branch matching an old commit.** The Dockerfile now fetches the pinned commit directly and initializes its recorded submodules. The source baseline is unchanged; branch movement no longer invalidates it.
- **P2 — documented startup omitted linked-worktree Git metadata.** `make dev-up` now supplies the common-Git-directory mount required by `git diff --check`. It handles paths with spaces and rejects comma-containing mount paths before starting a container. Tests exercise ordinary checkouts and real temporary linked worktrees through a recording CLI. The rebuild command preserves these mount arguments.
- **Documentation — loading/settings guidance contradicted Dux 2.0 sizing.** Instructions now distinguish widget thickness/inset, host padding, native scale options and standalone width. Development/review docs retain current contracts, evidence and outstanding acceptance instead of repeating past implementation narratives. Authorized external-change records in `CONFIGURATION.md` are preserved.

The first independent audit reproduced the pointer, Escape, hover-entry and tooltip defects with temporary behavior probes, confirmed the tooling problems and stale guidance, and reviewed the other runtime/tooling areas without additional actionable findings. Its initial baseline checks passed, demonstrating that direct-controller tests and arranged keyboard focus had missed important user-interaction boundaries.

## Architecture and style decisions

Retain the two independent plugins, one reactive compositor boundary in `NiriState`, host assumptions in `BarGeometry`, pure transformation/reorder models, and ID-based `ModelUtils` reconciliation. These match the product contracts and Dux's ownership of bars, settings, theme and launcher. The sidebar reuses `WindowStrip`; visual/reserved widths stay distinct. Workspace assignments remain session-local, favorite symbols alone persist, and icon selection never names or retains dynamic workspaces.

The favicon subscriber stays event-driven, coalesces bursts, ignores replaced-owner replies, bounds inline images and removes unreferenced files. Conservative title agreement avoids inventing browser/Niri identity. Packages remain independently relocatable, and installation preflight preserves existing content while refusing duplicate selected IDs.

Share the three strip controls through a local `StripControl` component, centralizing native geometry/style, tooltip and press wiring. Reuse `resetWheelState()` in reset handlers. Remove the unused `BarGeometry.availableWidth`/`availableHeight` aliases and the always-false, unused `floating` projection after tiled-window filtering. Keep explicit text geometry and comments explaining host rounding, animation, acknowledgment and metadata workarounds; those encode observed constraints. Small independent settings declarations do not justify an extra settings framework.

A compositor fork, second IPC subscriber, merged plugin, persistent workspace model, new geometry framework or dependency-pruning packager would add complexity without resolving an observed defect. Repeated snapshot transformations need profiling evidence before introducing caches. No fundamental architecture replacement is warranted by this review.

## Validation and limits

The baseline passed `make check test-qml`: 59 JS tests, 31 Python tests, 95 Qt component passes and 6 standalone-package smoke passes. The new regressions failed before the corresponding corrections: four vertical pointer cases, two horizontal tooltip cases, hover entry while held, missing control press tracking, and natural Escape focus. The existing horizontal pointer and vertical tooltip cases passed. Qt totals include initialization/cleanup.

The completed full run passes `make check test-qml`: 59 JS tests, 34 Python tests, 107 Qt component passes and 6 independent-package smoke passes, plus ESLint, Ruff lint/format, Prettier/model formatting, ShellCheck, manifest validation, zero-warning QML lint and patch whitespace. The revised Dockerfile builds successfully; a separate fresh network fetch checks out the exact Dux commit and recorded submodule without relying on Docker’s source cache. Updated `make dev-up` succeeds against this checkout’s container; temporary-worktree tests verify new startup arguments. The container uses Qt 6.11.2.

The second independent review confirmed the first audit’s coverage and architecture decisions, and independently reran the startup tests and whitespace check. It found the expand-button/hover race above, which the added regression reproduced before correction. The focused follow-up found no actionable issues and confirmed all prior findings resolved. It independently passed all 13 sidebar Qt checks, verified packaged components match source, inspected the pinned APIs and passed whitespace validation. It also reviewed the completed full-run log and final documentation without identifying regressions.

No desktop configuration, external project, machine-local skill or running shell was changed. Component checks cannot establish visible Dux/Niri behavior. [Runtime acceptance](DEVELOPMENT.md#runtime-acceptance) retains the unresolved checks: workspace edge pointer routing (including the earlier native missed-click report), fractional scale/style/inset/padding, native overflow parking and multiple growing widgets, popup/tooltip placement, real reorder acknowledgments/races, sidebar focus/input masks/exclusive zones, independent archive installation and settings migration. Historical DMS 1.6 acceptance does not prove Dux 2.0 behavior. Earlier implementation/review rounds remain in Git history.
