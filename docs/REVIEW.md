# Project review

This review covers the project from `b0d610b`: both plugin manifests/entry points, all runtime QML and JavaScript models, settings, session singletons, the favicon bridge, packaging/install helpers, development tooling, tests, and documentation. The review includes correctness, host compatibility, architecture, duplication, unused data, comments, and maintainability.

The compatibility target is Dux Shell 2.0.0 fork `0bd677b213a445d4012e37968f8beca0acd90012`, common-widget submodule `ebf5e6c002da1bdaa4aaa2f319fea7b8507abc42`, and Quickshell 0.3.1. The pinned source and local fork `c5b058c83e6ac77420e43b8e7dd844a652cef679` were inspected. There is no installed/active desktop shell in this environment; these sources cannot establish the user's running revision.

## Structure, style, and duplication

The independent Window Tabs and Workspaces plugins remain the right product boundary. Their shared host adapter and ID-based reconciliation avoid copying navigation state. The optional sidebar reuses the window strip and stays disabled by default. A compositor connection or persistent workspace model would duplicate responsibilities already owned by Dux/Niri.

The implementation keeps `NiriState` as the compositor boundary and `BarGeometry` as the host-layout boundary. The bar budget has moved from `WindowModel` into `BarModel.primaryBudget`, with named measurements instead of nine positional arguments. Workspace layout no longer depends on an unrelated window model. The existing budget behavior tests moved with the implementation; host integration regressions remain enabled.

The strip's repeated launcher/overflow sizing, theme, and tooltip bindings now live in one inline control component. Wheel reset paths reuse the existing helper. The workspace rail uses `WorkspaceModel.iconFor` instead of duplicating the custom/automatic/fallback lookup. Unused cross-axis budget aliases, the always-false filtered-window `floating` role, and the test-only `stripGeometry.viewportWidth` result are removed. The real viewport remains covered by component containment tests. Legacy pre-2.0 ancestry discovery is removed after confirming both pinned Dux section types use `SectionEntry`; startup still tolerates a missing repeater.

Small, independent button/settings declarations remain separate where their input behavior, native settings lifecycle, or module identity differs. There is no measured reason to replace `ModelUtils`' stable-ID reconciliation or the pure reorder state machine. Explicit text geometry remains necessary for the established real-host rendering contract.

Documentation now describes Dux widget thickness/inset rather than the old full-bar sizing behavior. Stale DMS 1.6 wording is removed from the title-display setting. Development notes summarize current API contracts and remaining checks instead of repeating implementation history. User-authorized desktop changes remain in `CONFIGURATION.md`; past experiments remain in Git.

## Coverage assessment

- **Window models and views:** output/workspace filtering, exact title and urgency handling, floating exclusion, stable monitor-based widths, compact rows, overflow, wheel accumulation, mouse-down activation, middle close, keyboard input, and real pointer drag initiation.
- **Reordering:** adjacent column/stack actions, neighbor/source focus staging, layout acknowledgment, dispatch rejection, timeout, outside cancellation, and surviving delegate/preview identity. Reactive host state remains the source of truth; no local persistent order is introduced.
- **Workspaces:** live-ID identity, trailing empty workspaces, assignments across all outputs, first-window seeding, removal, icon validation, favorites and legacy fallback, picker edges, selected-row visibility, and inset hit targets at whole/fractional sizes.
- **Dux host integration:** native controls/theme, scale/maximize preferences, pill rounding, effective padding, section siblings and overflow triggers, all four orientations, and config/delegate preservation. Budget computation avoids measuring its own growing section.
- **Sidebar:** opt-in daemon lifecycle, live output selection, fixed surface versus reserved width, overlay/push behavior, animation stability, retained scrolling/delegates, interaction holds, and mouse-established keyboard focus.
- **Favicons:** active-tab-only wire projection, cross-profile title agreement, conflicting/missing-image fallback, bounded inline images, cleanup, owner replacement, stale replies, burst coalescing, one delayed compatibility read, and process recovery. No new actionable bridge defect was established.
- **Tooling and packaging:** manifest confinement, shared-module link, conflict preflight, editor-import publication/rollback, missing-tool failures, pinned formatting dependencies, exact Dux source checkout, and linked-worktree Git visibility. No credentials, desktop configuration, or unrelated project files are changed.

## Validation and limits

The original baseline passed 59 JavaScript tests, 19 Python tests, zero-warning QML lint, the configured linters/formatters, and 93 Qt Quick passes including initialization/cleanup. The new regressions were run against the failing behavior before their corrections.

Current validation runs `make check` and `make test-qml` in the repository's Fedora 44 container. The source-fetch change also received a clean development-image build, and both startup and the corrected `--remove-existing-container` rebuild were exercised from this linked worktree. The fresh container regenerated imports successfully with its common Git mount. The current suite passes 60 JavaScript tests, 19 Python tests, and 108 Qt Quick passes including initialization/cleanup, plus all configured lint/format checks. The repository has no checked-in CI workflow; these are local verification results.

These are model, lint, and isolated component checks. Visible Dux/Niri acceptance remains pending for actual compositor reorder behavior, bar styles/outlines and fractional output scaling, crowded/fit-to-widgets bars, native overflow menus, tooltip/picker placement, workspace-edge clicks, and sidebar exclusive zones/input masks/keyboard focus. The active desktop revision must be discovered from its logs before that acceptance. See [Development](DEVELOPMENT.md#runtime-acceptance).

## Independent review

The first read-only agent audited `b0d610b` and reported six P2 findings (vertical pointer dragging, sidebar hover holds, pointer-established keyboard focus, tooltip clearance, source pinning, and linked-worktree setup) and two P3 findings (neutral wheel events and stale loading instructions). Each is addressed above. Its proposed model/host cleanup and documentation simplifications are also incorporated. It found the principal architecture sound and established no additional bridge, workspace-lifetime, packaging, or pinned-host API defect.

The second read-only agent reviewed the original audit and the full resulting diff after the first completed. It confirmed the principal architecture and the other corrections, then found two remaining issues: middle-button tab presses were excluded from the hover hold, and the documented rebuild command omitted the worktree Git mount. Both are corrected: all accepted tab presses participate in the hold, ending only when no accepted button remains; activation and dragging remain left-button actions. New left/middle pointer cases reproduce the middle-button failure before correction and preserve focus/close dispatch. The rebuild instructions now use `make dev-up DEVCONTAINER_UP_ARGS=--remove-existing-container`, sharing mount discovery with ordinary startup.

The second reviewer also identified a formatter-induced readability problem after the tooltip data factory. Explicit data records replace the inline mapping expression; the configured formatter restores normal indentation. The review found no additional concrete workspace-lifetime, delegate, reorder, favicon, or tooling-publication defect. Native acceptance remains outstanding as described above; neither agent claims static tests prove visible desktop behavior.
