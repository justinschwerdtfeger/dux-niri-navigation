# Codebase review — 2026-10-10

The repository now provides independent **Justin Window Tabs** (`justinNavigation`) and **Justin Workspaces** (`justinWorkspaces`). Both follow either horizontal or vertical DMS bars. Window Tabs also provides optional always-visible and expandable standalone sidebars, with independent title width, click/hover activation, and overlay/push reservation preferences. The installed and active API baseline remains DMS 1.6.2, Quickshell 0.3.1, and Niri 26.04. Preserve the established horizontal style and the existing workspace picker controls.

## Current implementation

| Area                 | Result                                                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plugin separation    | Window Tabs retains the old ID/settings; Workspaces has a separate manifest and thin wrappers sharing the checkout through `shared -> ..`                            |
| Vertical tabs        | Optional icons, rotated titles, or normal title rows; icons default; wider normal-title bars retain compact row heights                                              |
| Host integration     | Shared `NavigationHost` with distinct pill components, inactive-view unloading, cross-axis sizing, button-local hover, and axis-aware budgets                        |
| Dragging/overflow    | One primary-axis geometry model for either orientation; wrapper-based grab offsets support rotated buttons; ID-keyed dropped previews persist through acknowledgment |
| Workspace navigation | Horizontal row or vertical rail with bounded overflow; all four popup edges; legacy pinned-symbol fallback until the new plugin saves its own favorites              |
| Shared state         | Workspace instances share assignments; window instances share the favicon subscriber; each role avoids instantiating the other singleton through a second module URL |
| Packaging/tooling    | Install helper preflights both links, preserves conflicts/broken links, and is idempotent; manifest/QML checks include both packages                                 |
| Maintenance guidance | Documents describe role-independent orientation, compatibility keys, install/migration, validation limits, and current acceptance checks                             |

The earlier codebase review also introduced shared ID-based ListModel updates, one-pass icon/favicon indexes, pure reorder acknowledgment models, keyboard activation/focus feedback, inline-image cleanup, D-Bus discovery recovery, and enforced formatting/linting in an accessible devcontainer. The optional tab-detaching extension was removed at the user's request. These remain current implementation contracts; detailed past experiments belong in Git history.

## Validation

`make dev-check` passes in the running Docker devcontainer: both manifests, **59 JavaScript behavior tests**, **19 Python tests**, ESLint, Ruff lint/format, Prettier, ShellCheck, strict zero-warning QML lint, QML format consistency, and diff whitespace. Qt Quick Test reports **27 passes**, including six initialization/cleanup passes. The behavior cases exercise all vertical modes (including a wide normal-title bar), vertical drag/drop acknowledgment, horizontal workspace overflow/identity, entry-point role independence, four picker edges, legacy favorites, sidebar click/hover timing and interaction holds, reservation/monitor selection, and the retained model/interaction regressions.

The Qt tests use mocked DMS services and offscreen rendering. They do not establish actual DMS bar appearance or real Niri reordering. With explicit user authorization, migrated the existing left-bar workspace widget to `justinWorkspaces`, enabled it, and restarted the existing DMS service. The top bar retains `justinNavigation`; saved-settings comparisons confirm no other preference changes. Both plugins report loaded/visible, and startup logs show each entry loading on both monitors without plugin QML errors. See [Configuration](CONFIGURATION.md) for the backup and exact external changes. Repository installation does not change desktop preferences automatically.

The sidebar composite and daemon also load after restarting the existing shell. A hot rescan encountered a new-file case-mismatch error that disappeared after restart, consistent with cached directory metadata. User-authorized temporary native validation created exactly one sidebar layer on DP-2 in both modes. At a 240 px title width, a representative tiled window measured 2418 px with Off, 2178 px with pinned mode on either edge, 2370 px with the collapsed rail, 2370 px after overlay expansion, 2178 px after push expansion, and 2370 px after collapse. The eDP-1 window remained 1299 px wide throughout. DMS’s built-in plugin-toggle command expanded/collapsed the native panel without runtime errors. Restoring Off removed the layer and returned window sizes to their baseline; parsed plugin settings exactly match the backup. These are compositor layout measurements, not visual acceptance of title placement, hover, tooltips, keyboard focus, or drag interactions. Offscreen tests do not create the Wayland surface.

Hover collapse now keeps the strip in one layout mode and changes title visibility independently. New animated Qt Quick regressions reproduced an overflow scroll reset and an icon-size change on collapse before the fix; they now verify preserved manual browsing across collapse/reopening, surviving delegates, unchanged row/icon geometry at two font sizes, and no row entrance fade. Normal bar sizing remains automatic. The user confirmed this resolves the rerender effect. Expansion/collapse now animates a shared width with DMS’s short duration and standard easing, fading titles in/out while keeping icon/row geometry and manual scroll stable. Additional behavior tests cover intermediate motion, reversal, overlay/push reservations, and disabled animations. The user reported stutter with per-frame native surface resizing. The animation now runs inside a fixed-width native surface, with a visible-panel input mask so transparent space passes clicks through, and one target-based reservation update in push mode. Model/component checks verify constant surface width and reservation behavior through motion. Native smoothness and input-mask acceptance remain pending.

Native loading is verified, and the user confirmed that the migrated top tabs and left workspace rail look and behave as before. Visible acceptance of horizontal workspaces and vertical tab modes remains outstanding, along with the interaction checks below.

The earlier combined plugin was restarted with user authorization after a reload retained an old helper. It loaded without plugin QML errors, and the user reported improved release-time tab movement. That observation predates the split. The isolated acknowledgment-position regression also passes against the older animation implementation, so it does not independently reproduce the original jump. Rapid/partial acknowledgments, changing widths, overflow drops, multi-monitor budgets, unusual center modes, and both axes still require live acceptance.

## Favicon evidence

Read-only inspection matched all 12 Helium windows to valid favicon URLs and confirmed TabCtl helper/extension compatibility. TabCtl 2.3.0 omits favicon-only notifications. With explicit authorization, the separate TabCtl source was patched to emit on favicon changes/completed loads; all 36 extension tests passed. The user loaded the local 2.3.0.1 build. A fixture changed only its icon after six seconds, the actual subscriber emitted distinct snapshots, and the user confirmed DMS changed from red to green. See [Configuration](CONFIGURATION.md).

That evidence establishes late event delivery for the fixture, not all remote-image loading or cache behavior. Matching, event delivery, and Qt image readiness remain separate checks. Workspace lifetime/ID reuse and broader visible acceptance limits are listed in [Development](DEVELOPMENT.md#runtime-acceptance).
